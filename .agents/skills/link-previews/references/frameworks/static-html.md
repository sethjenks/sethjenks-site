# Link Previews: plain HTML

A static site with no build step and no package manager, run locally by a small server (a few lines of Node, a dev script). Capture, the endpoints and the tag list are in [../adapters.md](../adapters.md).

## Dev-only folder

- One folder holds everything dev-only: the tool page, its scripts and stylesheet, the request handler for the endpoints and source route, the manifest, the sources and the wire script (for example `tools/link-previews/`).
- The server imports that handler only in development (for example, unless `NODE_ENV=production` or a `--production` flag) and passes it every `/link-previews/*` request. The handler serves the tool's own files from its folder and answers the endpoints; everything else is served as before. In production the folder is never loaded or served.
- The folder must also never be uploaded. With no build step that's a rule, not a mechanism: write it in the agents file and the README, next to how the site is deployed, and keep the folder out of any deploy script or ignore list the project has.
- Use only the platform's built-ins (`node:http`, `node:fs`, `node:crypto`). Add no packages.

## Wire script

Plain HTML has no imports, so a small dependency-free script (Node built-ins only) plays the metadata helper. It:

1. **Reads** the manifest and, for each entry, the page's HTML file (`/` is `index.html`; `/work/first-project` is `work/first-project/index.html` or `work/first-project.html`, whichever the site uses).
2. **Takes title and description from the page.** The title is the entry's `title` with line breaks collapsed. The description is the page's existing `og:description`, else its `<meta name="description">`. Never invent one; if a page has neither, leave `og:description` out and list the page.
3. **Builds URLs in the site's own form**: `SITE_URL` plus the path, with the trailing slash added back if the site's URLs end in one (as its sitemap or links show), so `og:url` matches the canonical URL. Image URLs as the helper builds them, with width and height from the PNG's header: `<SITE_URL>/og/<id>.png?v=<version>`, or the site's default image with its real size. When the entry has a `video`, the video tags too, with `<SITE_URL>/` plus the file's public path and `?v=<version>` when it has one.
4. **Writes one marked block** inside `<head>`:
   ```html
   <!-- link-previews:start (generated by <script path>; edit the manifest, not this) -->
   …the tags…
   <!-- link-previews:end -->
   ```
   If the block exists, replace everything between the markers. If not, first remove any existing share tags outside a block (`og:*` and `twitter:*` metas, keeping unrelated ones such as `description`), then insert the block right after `<meta name="description">`, else before `</head>`.
5. **Is safe to run twice**: the same manifest produces byte-identical files, and a file whose new content equals the old isn't written. Escape `&`, `"` and `<` in attribute values.
6. **Reports** what it changed and which pages it skipped (no HTML file, no description, no saved image).

Its output goes stale whenever an image is saved, because the `?v=` changes. Run it after every save, and say so in the agents-file rule.
